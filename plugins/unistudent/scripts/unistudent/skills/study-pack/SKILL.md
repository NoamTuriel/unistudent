<!-- conventions: keep identical in every UniStudent skill -->
Conventions. `us <command>`: the UniStudent tool for that command, the MCP tool named by its words joined with `_` (`us wiki build` → `wiki_build`, options as named arguments) when the unistudent MCP server is connected; otherwise run `unistudent <command> --json` in a shell (inside the plugin: `python3 <this skill's base directory>/../../../us.py <command> --json`; `python` on Windows). **Delegate** to a worker: its instructions are in `<this skill's base directory>/../../agents/<worker>.md` (if that file isn't there, get them with `us doc <worker>`); as the Claude plugin, give them to the plugin's subagent of that name, which has the UniStudent tools (in parallel when there are several); in any other app, follow them yourself, one at a time. **Ask**: use your question tool if you have one, otherwise ask in the chat.
<!-- /conventions -->

## 1. Course and unit

Run `us courses current` and say which course. Get the unit number from the student's request, or ask.

Done when: you have the course and the unit number.

## 2. Update or build

Run `us study changes --unit N --json`: its `pack_folder` is where the unit's pack lives in the Study vault (the study folder; `<pack folder>` below). The recordings roadmap in that folder is generated by the Wiki build: never edit it.

- The student asked to update the pack or what changed, or `has_study_pack` is true and the request names no page to rebuild: the update flow. With changes, read the new and changed Wiki pages (in the hidden Wiki) and draft a change list ("2 new questions for topic 3 from <source>: add them?"). Apply only what the student approves, then run `us study mark-built --unit N`. With none, say the pack is up to date. Stop. Study packs belong to the student: change only what they approve.
- Otherwise it is a build: go on to step 3. A build runs unattended from here to the end of step 6: the student has walked away, so every decision comes from the request, the rules and the course.

Done when: the update flow ended, or you are building.

## 3. Resolve the rules

Read, in this order (later wins):

1. the generic rules: `<this skill's base directory>/../../reference/study-pack.md` (or `us doc study-pack`);
2. General preferences;
3. Course preferences, `course-preferences.md` (both paths are in the course context, `.unistudent/context.md`).

Done when: you know the page list, each page's content rules, and the concept structure.

## 4. Pages

Resume: the pages to build are the rules' page list minus `pages_present` (the pages already in the pack folder); a present page is rebuilt only when the request named it. Say in one line which present pages you skipped. The recordings page exists only when a recorded lesson covers this unit: read the first line of each summary in the Recorded lessons recordings (the Wiki's `recordings/` folders of recordings assigned to `lessons`) and keep the ones that say they cover the unit. A unit with only solution recordings gets no recordings page; say so in one line. When `lessons_without_roadmap` is non-empty, run `us wiki build` first, so every lesson the recordings page links has its entry in the Recorded lessons roadmap.

Done when: you know the pages to build and, for the recordings page, which lessons it points to and that each has its roadmap entry.

## 5. Build

**Delegate** to one `study-pack-writer` worker, giving it: course folder, unit, the pack folder, the pages to build and the covering lessons, the resolved rules (paste them in full: the worker can't see your skills), the format (Obsidian or Markdown), and the language.

Save the writer's return, exactly as returned, to `.unistudent/writer-returns/<pack folder name>.md` in the course folder (the check in step 6 checks its shape). Act on its Known gaps: every `source` or `question` gap goes in your closing message to the student in one line each.

Done when: the writer's return is saved.

## 6. Verify

**Delegate** `<pack folder>` to the `verifier` worker. Fix what it reports, then run it again.

Done when: `us check --labels "<pack folder>"` reports 0 problems.

Then run `us study mark-built --unit N`.

## 7. Change requests during the session

Follow "Change requests" in the course context (`.unistudent/context.md`). Save with `us prefs add --scope course|general --text "<the rule>"`.

Done when: every whole-unit change the student asked for is saved at the scope they chose.
