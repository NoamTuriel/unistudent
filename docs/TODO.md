## Known gaps in what shipped
- **Transcription needs a yes for each recording.** Owner's words: the plugin transcribed the wrong videos for 5 hours; the setup must prompt for each video so the student has to say yes, because analysing is such a big thing. Today `course-setup` asks one yes/no for the whole course (recording level 0, 1 or 3) and `course-recordings` asks about "all of them" at once, so a wrong batch runs unnoticed. Change, in this order:
  1. **Prompts first, nothing runs.** For every recording, one prompt that names the file by its full path ("The video at `<full path>` will be transcribed. It is X long, estimated Y on this machine."), with yes or no. The student goes through all of them and picks the ones they want.
  2. **Then one go.** Only after the last prompt does the analysis start, for the chosen recordings, with a line like "Sit back and relax, this might take a while." The student can keep working, as `--background` already allows.
  3. **Enforce it in the tool, not only in the skill text**: `us recordings transcribe` takes the paths the student approved and refuses a path that was not chosen (no "transcribe everything" default), so a skill that skips the prompts cannot start a 5-hour run.
  Add a test that transcribing with no approved list does nothing, and that the skills name the per-recording prompt before the first transcription. Keep the separate frame-analysis question.
- **Links are everywhere; one place per topic is enough.** Owner's words: too much bloat with links; the end of each topic should say when in the lectures it was talked about, and the source link is not needed every time. Today every paragraph, question and graph caption carries a `file:` link (ticket 16). Change: no link on each paragraph; each topic ends with one short "In the lectures" line (recording and time, linked once). Open point to settle first: the ✅ label promises the student can check a claim against the course, so decide where that check lives (the line at the end of the topic, plus the source file named once) and update ticket 16's rules, the `us check` link tests and `reference/study-pack.md` to match.
- **Accepted reasoning belongs inside each topic, not in its own section.** Owner's words: how to answer verbal questions should be part of the subject, not a completely different section. 0.5.1 put it on the roadmap page as separate blocks. Change: in the walkthrough, each topic gets its accepted reasoning (say it, take as given, prove it, model answer) right after its concepts; the roadmap only points to it. Update the generic rule and the economics rule together.
- **The Practice page (`N.3`) is too heavy.** Owner's words: too much bloat and over-complication in the exercise page. What the generic rules put on it today: every question of the unit, grouped by topic and by four stages (slide examples, questions with answers, the assignment, past exams and combined units), each with a topic tag, a source link and a recording time, plus graphs where the course draws one, and a separate Short practice page (`N.3b`) for the same questions. Next step: ask the owner which parts of a real Practice page get in the way (stages, tags, the links, the graphs, or its length), then cut to what a student needs to solve a question: the question, where it came from, and where it is solved. Judge any cut against the student's flow in `reference/study-pack.md` ("practice" is step 3 and step 4).
- **Graphs: the student is asked to install matplotlib that the MCP tool already has.** Seen by the owner: the AI said matplotlib was missing and asked them to install it, and after they tried and failed it said the UniStudent tool server already has matplotlib and drew the graph through it, which cost time. Cause to check: `.mcp.json` runs the MCP server with matplotlib, but the plain `us` command (and its `INSTALL_HELP` text in `graph.py`) does not, and `reference/study-pack.md` step 5 tells the AI to tell the student how to add it. Fix to spec: try the MCP `graph` tool first; ask the student to install anything only when the tool itself reports matplotlib is missing, and never as a first step. Add a test that the skills' graph instructions name the MCP tool first.
