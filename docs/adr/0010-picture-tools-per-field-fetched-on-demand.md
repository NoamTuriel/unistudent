# Picture kinds, each fetching its own tool on demand

A Study pack should look like the course teaches. Graphs (ADR 0006) fit economics; other fields teach with other pictures (circuits, structures, constructions). So `us draw <kind> <spec>` is one dispatcher with one small drawer per kind, each declaring the one library it needs. This builds on ADR 0006, which stays the decision for X-Y Graphs.

The library is not part of the server's launch. When the kind's package is not importable, the same command runs again in `uv run --with <package>`, which downloads and caches it: no restart and no config edit, the same on Windows, macOS and Linux, and `uv` is already required. This supersedes ADR 0006's exception that put matplotlib in the default launch; matplotlib is now the first kind and fetches itself on first use, without asking, because every graph needs it. If the fetch fails, the Study pack links the slide page and describes the picture in words, so nothing blocks.

A tool qualifies only if it is free, needs no account or key, runs offline on all three systems, installs in one step, and is driven by a short text spec. A kind is added when a real course shows that picture, not in advance: `us draws` lists the kinds, and each Study pack ends its How-to-start with "The plugin now supports: X, Y, Z", so a student who sees a picture learns they can ask for it in chat.

We chose this over adding every library to the default launch (every student downloads what only some need) and over a third-party Desmos or GeoGebra MCP (ADR 0006's reasons still hold). Mermaid flows are unchanged and are listed as supported.

**Amended (2026-10-03), dropping the tool offer this ADR originally also decided.** The first version of this ADR recorded two decisions at once: fetch-on-demand, and a one-time offer before the first Study pack asking the student which picture tools to add (at most three, chosen from keywords found in the course Wiki, the answer remembered in the course settings). The two were in tension and nobody noticed: fetch-on-demand removes the download cost the offer existed to ask permission for. `graph` proved it in practice — the most-used kind installs itself with no question, no record and no complaint, and every other kind behaves identically.

The offer also never once fired. Its evidence keywords were English, so a Wiki in any other language matched nothing, and its field fallback was gated behind a near-empty Wiki, so a real course never reached it. Measured on the only real course (Hebrew, 2.2M characters): no tool offered, for its own field or any other. That was the symptom; the dissolved premise was the cause.

So `us tools offer|accept|skip|status`, the keyword scan, the per-course record of answers and the Study-pack step that ran the offer are removed, along with the circuit, molecule and tree kinds, which no real course had asked for and whose drawers had never been checked against a course's own picture. What survives is the part that earned its place: one dispatcher, one line plus one small file per kind, and a tool that arrives when a picture needs it. The follow-on work the offer implied — a subagent scanning the Wiki, a live search for packages, agent-written drawer scripts — is not deferred but dropped: it existed only to feed the offer. The spec's own Out of Scope ("a live, per-student internet search for tools") stands.
