# Generated university fallbacks are interviewed once, then cached

When no plugin exists for a student's university, the plugin interviews the student once (site URL, how they organize material) and writes the result to a local reference file, in the same shape a hand-authored plugin would use (e.g. `plugins/openu/skills/openu-sync/references/site.md`). It is never re-researched live in a later session. We chose this over live per-session lookup because most AI tools this plugin supports have no reliable browsing capability, and unverified live scraping-instruction generation risks silently missing or misreading a site with no one noticing; a cached, student-confirmed file behaves identically to a hand-authored plugin from then on, including in tools with no browsing capability at all.

**Precedence: an installed plugin always wins.** A generated fallback is only used when no plugin is installed for that university. If a real one is installed later, it takes over the next time `course-setup` runs; the generated file stays on disk, unused, until the student deletes it (`us generated list` shows what exists). We chose this over "the fallback stays authoritative" because a hand-authored plugin is maintained and the fallback is one unverified description from one student.

Narrowed by ADR 0011: per-course study-pack rules are no longer generated; only the university fallback remains.
